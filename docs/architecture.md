# Architecture

Neoactyl is a SvelteKit application with a single long-lived Node/Bun process. This document is a map of the moving parts; it is not an exhaustive API reference.

## Stack

| Layer          | Technology                                                        |
| -------------- | ----------------------------------------------------------------- |
| Framework      | SvelteKit 3 with Svelte 5 runes                                   |
| Language       | TypeScript                                                        |
| Build tool     | Vite                                                              |
| Styling        | Tailwind CSS, shadcn-svelte, bits-ui, Tabler icons                |
| Database       | SQLite/libSQL through Drizzle ORM                                 |
| Authentication | Better Auth (email/password and optional Discord OAuth)           |
| Payments       | Stripe checkout and webhooks for credit top-ups                   |
| Integrations   | discord.js for the invite bot; `ws` for the AFK WebSocket gateway |
| Runtime        | Bun in development and production, `@sveltejs/adapter-node` output |

## Request flow

Most requests go through `src/hooks.server.ts`:

1. Start one-time server initialization (`initializeServer`).
2. Apply a rate limiter to sensitive endpoints.
3. Ensure the operational schema exists and load cached settings.
4. Resolve the Better Auth session and attach the user to `event.locals`.
5. Delegate to SvelteKit, then add security headers and record timing metrics.

Unexpected errors are captured by `handleError`, stored in the error log, and shown to the user with a reference ID.

## Routes

| Route group        | Purpose                                                                 |
| ------------------ | ----------------------------------------------------------------------- |
| `/setup`           | One-time first administrator and adapter setup                          |
| `/auth/*`          | Login, registration, and logout                                          |
| `/dashboard`       | User overview                                                            |
| `/server/*`        | Server console, files, backups, schedules, databases, and settings      |
| `/storefront`      | Purchase server plans and other items with credits                       |
| `/credits`         | Balance and top-ups                                                      |
| `/afk`             | Earn credits by staying active                                           |
| `/rewards`, `/j4r` | Reward tasks and Discord join-for-reward flows                          |
| `/invite`          | Discord invite rewards                                                   |
| `/admin/*`         | Server, user, storefront, economy, software, node, log, and settings UI |
| `/api/adapter`     | Authenticated RPC endpoint that exposes the selected adapter             |
| `/api/auth/*`      | Better Auth and Stripe webhook endpoints                                |
| `/api/afk/*`       | AFK session setup and internal gateway ingest                            |

Server-only modules live under `src/lib/server` and are imported with the `#lib/*` alias. Browser code talks to the adapter through `src/lib/adapter/client.ts`, which posts method calls to `/api/adapter`; the server validates the session and dispatches to the adapter.

## Adapter layer

The adapter layer is the boundary between the panel and a game hosting backend.

- `src/lib/adapter/sdk.ts` defines the contract: `Adapter`, capabilities, and normalized types such as `Server`, `Node`, `Backup`, and `Schedule`.
- `src/lib/adapter/client.ts` is the typed browser client used by Svelte components.
- `src/lib/server/panel/adapter.ts` selects and caches an adapter from panel settings. It also wraps calls with error normalization, activity logging, and per-user ownership checks.
- `src/lib/server/panel/calagopus.ts` and `mock.ts` are the current implementations.

Adapters declare capabilities so the UI can hide unsupported features. Required methods throw `AdapterError` with a normalized code (`UNAUTHORIZED`, `NOT_FOUND`, `VALIDATION`, `NETWORK`, `UNSUPPORTED`, and so on), which the server logs and the UI can display safely.

See [Adapters](adapters.md) for implementation details.

## Data layer

The database is accessed with Drizzle ORM over libSQL. There are two schema sources:

- `src/lib/server/db/auth.schema.ts` is generated by the Better Auth CLI.
- `src/lib/server/db/schema.ts` and the files it re-exports define the panel's own tables.

`src/lib/server/db/bootstrap.ts` creates many operational tables with `CREATE TABLE IF NOT EXISTS` and performs small additive migrations at startup. This lets new features work on older databases without a manual migration step. Larger or destructive changes belong in Drizzle migration files under `drizzle/`.

`src/lib/server/config/settings.ts` stores configuration in a key/value table with defaults and an in-memory cache. Secrets such as panel tokens are encrypted before storage.

## Background work

`src/lib/server/lifecycle.ts` starts background work on the first request, not at import time:

- **Renewals** run roughly every minute. Renewals may suspend or delete servers according to the configured interval and grace period.
- **Discord bot** starts in the web process when `DISCORD_EMBED_BOT` is enabled. It can instead run separately with `bun run bot`.
- **AFK gateway** is attached to the same HTTP server as the app. `server.ts` imports the adapter-node build and attaches the WebSocket server, so the AFK socket shares the app's port, process, and TLS termination.

Because of the AFK gateway and background timers, production runs a single Node process rather than a serverless platform. Scale vertically, or run separate instances with a shared external database only if you understand how the timers and Discord shards interact.

## Frontend structure

- `src/lib/components/ui` contains shadcn-svelte primitives.
- `src/lib/components/app` and `src/lib/components/admin` contain panel-specific UI.
- `src/lib/panel` contains shared panel runtime pieces: blueprint rendering, prompts, feedback, and state.
- Svelte 5 runes are enabled for project files in `vite.config.ts`.

## Security boundaries

- Never import `src/lib/server` code into client components.
- API tokens and integration secrets stay in the database or environment, never in the client bundle.
- The adapter RPC endpoint requires an authenticated session and applies rate limits.
- Server operations for adapters that support panel accounts are scoped to the linked panel user.
- Responses include CSP, HSTS (on HTTPS origins), and other security headers from `hooks.server.ts`.
